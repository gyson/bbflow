bbflow 0.0.26 lets you choose the permission mode of each agent, moves updates to
Settings with a **Check now** button, and stops a session or its family from the
sidebar. Idle Claude Code sessions now stay idle.

## What changed

- A built-in tool now has a **Permissions** menu next to **Model** and **Thinking
  effort**. It is **Default permissions** in the tool editor of Settings, and
  **Permissions** in a draft and in **Continue in new terminal**. The choices are the
  modes of each CLI, with the names that the CLI shows, such as **Approve for me** of
  Codex or **Accept edits** of Claude Code. bbflow adds the options of the mode to the
  startup command, for example `codex --no-alt-screen --approve-for-me`. **CLI
  default** adds no option, so the CLI keeps its own setting, as before. Shell and
  Custom tools have no menu.
  [Add your tools](https://github.com/gyson/bbflow/blob/v0.0.26/docs/GUIDE.md#add-your-tools)
  and
  [Permission modes](https://github.com/gyson/bbflow/blob/v0.0.26/docs/SPEC.md#permission-modes)
- The update controls moved from the sidebar to the **Updates** card of Settings. The
  card shows the running version, the result and time of the last release check, and
  the reason of a failed check or update. **Check now** checks at once, also when
  **Check for a new version every day** is off. A dot on **Settings** in the sidebar
  tells of a newer version, and a red dot tells of a failed update. A click on
  **Settings** with the dot opens the **Updates** card.
  [Update bbflow](https://github.com/gyson/bbflow/blob/v0.0.26/docs/GUIDE.md#update-bbflow)
  and
  [Update from the web UI](https://github.com/gyson/bbflow/blob/v0.0.26/docs/SPEC.md#update-from-the-web-ui)
- A failed release check now reports the last installer message, such as `cannot
  read release; check the version and GitHub access`, instead of `exit status 1`.
- The ⋯ menu of a live session in the sidebar now has **Stop session**. The menu of
  a top-level session also has **Stop family** while one of its sub-sessions is live.
  **Stop family** stops every live member, also the top-level session. Both items ask
  first in a dialog that lists the sessions and their status. Side terminals continue,
  and the history stays.
  [Work in a session](https://github.com/gyson/bbflow/blob/v0.0.26/docs/GUIDE.md#work-in-a-session)
  and
  [Stop from the sidebar](https://github.com/gyson/bbflow/blob/v0.0.26/docs/SPEC.md#stop-from-the-sidebar)
- An Antigravity session in a managed worktree now starts without the question "Do
  you trust the contents of this project?". bbflow adds a session-only
  `--settings '{"trustedWorkspaces":[...]}'` option for the session folder.
  Antigravity does not save it. bbflow does this also when you did not trust the
  project folder in Antigravity. Use a worktree with Antigravity only for a
  repository whose files you trust.
  [Tool types and models](https://github.com/gyson/bbflow/blob/v0.0.26/docs/SPEC.md#tool-types-and-models)
- An idle Claude Code session no longer shows **Running** and moves to the top of the
  sidebar every 30 minutes. Claude Code shows `Checking for updates…` for a short time
  and then erases it. A screen change now counts as activity only when it lasts. A
  short burst of changes that leaves the screen as it was within 1 second does not
  count. **Running** now shows up to 1 second after a lasting change starts.
  [Activity detection](https://github.com/gyson/bbflow/blob/v0.0.26/docs/SPEC.md#activity-detection)
- On a phone, a scroll in the session terminal or the side terminal no longer opens
  the keyboard. This applies to a vertical drag and to a touch that stops a glide. A
  tap still focuses the terminal and opens the keyboard.
  [Touch scroll in a terminal](https://github.com/gyson/bbflow/blob/v0.0.26/docs/SPEC.md#touch-scroll-in-a-terminal)

## Command changes

- `bbflow settings set update-check false` now stops only the daily check. **Check
  now** in Settings still checks.
- `bbflow query` can read the new `permission` key of each tool in `settings.data`
  and of each `preparations.data`. In a managed worktree, the command of an
  Antigravity `start` event includes the trust option. `bbflow skill` describes both.
- The server now sets the `events.quiet` flag of an `output` event up to 2 seconds
  after it records the output, so a query can see `0` for that time. `bbflow skill`
  describes the new rule.

## Upgrade from 0.0.25

When the sidebar offers the update, open the offer and review the sessions that
will stop. Select **Update and restart** to install the release and restart the
server. You can also run `bbflow update` from a terminal outside bbflow. From this
release, later updates show in the **Updates** card of Settings.
[Update from the web UI](https://github.com/gyson/bbflow/blob/v0.0.26/docs/SPEC.md#update-from-the-web-ui)

The first start upgrades SQLite format 21 to format 22. It preserves history and
settings. Each saved tool and each draft gets **CLI default** permissions, so each
launch submits the same command as before. Open tabs reload once after the restart
to load the new UI.
[Formats](https://github.com/gyson/bbflow/blob/v0.0.26/docs/SPEC.md#formats)

## New installation

```sh
curl -fsSL https://github.com/gyson/bbflow/releases/latest/download/install.sh | sh
bbflow server start
bbflow ui
```
