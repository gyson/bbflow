bbflow 0.0.8 is the first release under the new name. BonBon is now bbflow. Use
`bbflow migrate` to copy your BonBon history into bbflow.

## What changed

- The product, the command, and the executable are now `bbflow`.
- bbflow keeps its data in `~/.bbflow`. BonBon used `~/.bonbon`.
- Environment variables use the `BBFLOW_` prefix, for example `BBFLOW_DIR`.
- Managed worktree branches use the `bbflow/` prefix.
- The server uses protocol `bbflow/24`.
- `bbflow migrate` copies the history of a stopped BonBon instance into bbflow. It
  verifies the copy and does not change the BonBon data.

## Move from BonBon 0.0.7

BonBon 0.0.7 is the last BonBon release. `bonbon update` cannot install bbflow, because
bbflow is a separate app. Install bbflow, then copy your history once, before the first
bbflow start:

```sh
curl -fsSL https://github.com/gyson/bbflow/releases/latest/download/install.sh | sh
bonbon server stop
bbflow migrate
bbflow server start
bbflow ui
```

`bonbon server stop` ends active BonBon sessions. `bbflow migrate` copies
`~/.bonbon/history.sqlite` into `~/.bbflow`. It checks the integrity of the copy and
compares the row count of each table with the source. Then it upgrades the copy. It
accepts history from every BonBon release. Sessions, terminals, recordings, drafts,
attachments, projects, and settings come with the copy.

Copied sessions keep their recorded workspace paths. A session that used a folder
inside `~/.bonbon`, such as a managed worktree, still uses that folder. The command
lists these folders. Keep them until you finish with those sessions.

While `~/.bbflow` has no history and `~/.bonbon` has history, `bbflow server start`
stops and tells you to run `bbflow migrate`. To start without the BonBon history, use
`--dir` with another directory.

When you no longer need BonBon, remove the `bonbon` executable and `~/.bonbon`
yourself.

## Install

```sh
curl -fsSL https://github.com/gyson/bbflow/releases/latest/download/install.sh | sh
```

The installer selects the Apple Silicon or Intel archive, verifies its checksum and
version, and installs to `~/.local/bin`. Run `bbflow server start` and `bbflow ui` to
open bbflow.

## Release checks

The Release workflow runs `make test`, `make check`, `make web-check`, and a native
release smoke check on Apple Silicon and Intel before it publishes the archives.
